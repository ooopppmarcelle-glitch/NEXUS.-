# NEXUS³ — Initial Roadmap

This roadmap is directional. A phase is complete only when its acceptance criteria are met and evidence is recorded.

## Phase 0 — Foundation
- [x] Establish product vision and foundational principles.
- [x] Define initial AI collaboration responsibilities.
- [x] Define evidence-based completion and human approval rules.
- [ ] Review and approve the technical architecture.
- [ ] Record architecture decision records.

## Phase 1 — Technical skeleton
- [x] Inspect the initial Google AI Studio scaffold and identify the current application stack.
- [x] Restore core project documentation alongside the application scaffold.
- [ ] Verify dependency installation and production build.
- [ ] Add automated tests and a repeatable test workflow.
- [ ] Complete authentication, authorization, and security review.
- [ ] Verify PWA installation and offline behavior.

## Phase 2 — Core MVP
- [x] Initial mission management and workflow stages.
- [x] Initial project memory and decision records.
- [x] Initial proof and repair workflow.
- [x] Initial governance policy and audit log.
- [ ] Complete founder command center and project overview.
- [ ] Validate mission contracts and acceptance criteria.
- [ ] Harden evidence and validation records.
- [ ] Add authenticated audit trail and approval workflow.

## Phase 3 — Provider integrations
- [x] Initial Gemini API adapter.
- [x] Manual Relay packet flow for external assistants.
- [ ] Define and test a common provider adapter interface.
- [ ] Add explicit configuration for supported AI providers.
- [ ] Add timeouts, retries, rate-limit handling, and failure reporting.
- [ ] Test provider isolation and permission boundaries.
- [ ] Add a human-readable history of provider actions.

## Phase 4 — Reliability and release
- [ ] Security review and remediation.
- [ ] Automated test suite and build verification.
- [ ] Accessibility and responsive-interface review.
- [ ] Backup, recovery, and observability plan.
- [ ] Founder acceptance review.
- [ ] Release only after the release checklist passes.

## Release rule
Do not mark a roadmap item complete based on a plan, mockup, or generated code alone. Record the implementation location and validation evidence.
